Routes

Home
Branded landing. Logo, headline, one-paragraph description, CTA → Data Sources. Marketing-style layout (own personality, same tokens).
/datasources
Data Sources
Table of all uploaded files: name · type · uploaded date · rows. Click row → preview. "+ Add data source" button → upload dialog.
/reports
Reports
List of all reports: name · data source · created. "+ Add Report" button → Add Report dialog. Click row → report detail.
/reports/:id
Report Detail
Header: report name + description. Canvas: one chart widget. "Add Widget" button → Chart Builder dialog (existing spec).
/styleguide
Style Guide
Read-only — every token, scale, rule rendered live. Tooling, not user flow.
Dialogs (overlay — no route change)
from /datasources
Upload Dialog
Drop zone · accepts CSV/Excel · parses with PapaParse/SheetJS · system-inferred types only (no editing here). On save → data source added to list.
from /reports
Add Report Dialog
Step 1: pick a data source (or "+ upload new" → opens Upload Dialog inline)
Step 2: name + description
Step 3: column config (type overrides, renames, ignore toggles) — scoped to this report
Save → routes to /reports/:newId
from /reports/:id
Chart Builder Dialog
The existing 4-step stepper from the whitepaper. Unchanged from the v2 spec. Save → chart appears on report detail.
Happy path (first-time user)
/ Home → /datasources → Upload Dialog → /reports → Add Report Dialog → /reports/:id → Chart Builder Dialog → Chart on canvas
Open decisions before whitepaper rewrite
  1. Charts per report: ✅ one (locked)
  2. Column config location: data source has system-inferred types only · per-report overrides for type/rename/ignore — or both layers?
  3. Branding scope: same tokens with different layout/feel — or fully bespoke style (separate fonts, colors)?
  4. Cross-references: can a data source be deleted if reports depend on it? Block, or cascade-delete reports?
  5. "Try with sample data": still on the Upload Dialog (creates sample data source), or a separate "+ Add sample data source" affordance on /datasources?
